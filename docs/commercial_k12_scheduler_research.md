# K12 排课示例域调研摘要

> 本文档保留为 K12 示例域资料，用于说明一个复杂业务场景如何迁移到规则优先的 AI 运筹优化框架。它不再代表仓库的唯一开源定位。

## 真实中国 K12 学校教务人员

目标用户是中国 K12 学校的教务主任、年级组、排课老师和信息化支持人员。他们通常不会先更换全套系统，而是要求排课工具能承接现有 Excel、年级规则、晚自习和值班安排，并能把异常解释清楚。

## 外部信号

- 来源：Timefold school timetabling 示例把课程、教师、班级、教室、时间片和约束拆成可复用模型，说明“学校排课”适合做成可解释的约束问题。
- 来源：国内学校常见采购更关注落地服务、数据迁移、试运行和结果可追责，而不是单纯算法宣传。
- 来源：一线排课流程仍大量依赖 Excel/OA 表格流转，系统必须支持模板下载、导入预览、人工确认保存和变更回滚。

## 学什么

- 用 `SchoolProfile` 描述学校作息、学段、日历和值班制度，避免把单校口径写进求解核心。
- 用 `RuleInstance` 和 `RuleExecutionPlan` 把规则模板、学校参数和实际调用轨迹连起来，便于跨校复用与审计。
- 用结果交付清单、根目录 `status.json` 和结果包完整性检查来说明当前批次能否正式使用。
- Web 主流程优先服务真实教务动作：数据准备、规则校验、求解运行、诊断处理、课表预览、结果导出。

## 舍弃什么

- 不把复核/签核做成系统主功能。真实学校可以沿用 OA 或线下审批，本系统当前重心回到排课规则、已排课表微调、课表统计、结果追踪和教务可操作性。
- 不把设计原型、营销稿、截图快照和历史审计材料保留在主仓库作为交付文档。
- 不让诊断试跑、排障包或缺少正式状态的批次伪装成正式课表交付。
