# 按学校业务定义排课问题

2026-10-04，依据用户对产品目标的明确修正：通用中小学排课系统的核心是表达业务需求。联合排课、白天、晚自习、周中、周末是可能出现的业务分类，不是系统必须采用的模型边界。小学、初中、高中是验收样本，也不是三套固定求解策略。

## 已落地的第一步

新增 `course` API 入口和独立课程编译路径。学校自行命名时间格，例如课程1、社团1、夜间研学1；自行启用上课日；按整个配置周期提供学科课时及班级差异。课时不强制拆成早自习、周中、周末。可用课位允许留空，固定课程计入学科需求，固定非教学活动另占课位。

新路径只执行结构约束和已确认、可编译的 Rule V2，不继承旧学校的教师姓名、早自习交替或周末策略。旧路径保留兼容。旧目录中的学校特有策略不会因此自动获得新路径支持，需迁移为明确的规则原语。新路径当前完整支持教师禁排、每日课时上限、受支持的时段偏好、规则例外和系统结构规则；不存在匹配对象或不支持的启用规则会阻断。

输入仍复用现有 Web 表格 API；`day_rules` 是兼容字段名，不代表新路径只能排白天。通用领域模型尚未彻底取代旧输入类型，本阶段是接通业务配置到实际模型，后续需要合并输入合同，避免长期维护两个事实源。

| 表 | 新路径字段 |
| --- | --- |
| 教师定位 | 班级，以及实际学科对应的教师列 |
| 时间格 | 时段节次，例如社团1，以及启用星期的 0/1 列；也接受时段、节次分列 |
| 学科课时 | 学科、周期课时 |
| 班级课时差异 | 班级、学科、周期课时 |
| 固定安排 | 作用范围 ALL/CLASS、班级、星期、时段、节次、学科或活动名称 |
| 学科禁排 | 学科、禁排星期、禁排时段、节次或 ALL |

`/api/day-rules/template?table=subject_hours&mode=course` 可下载对应模板。导入只生成预览，保存后才进入学校工作区。规则仍需用户明确确认后激活。自然语言解析使用上传的时间格，模型不可用时保留本地解析；不会猜测不存在的时段。

## 当前验收证据

可执行入口：`verification/fixes/k12_api_acceptance.py`。

```powershell
.venv\Scripts\python.exe verification/fixes/k12_api_acceptance.py --output-dir outputs/k12_acceptance_new_run
```

输出目录必须不存在。脚本复制必要运行代码到全新的隔离目录，创建匿名 SQLite 工作区和管理员，启动仅监听回环地址的 Web 与独立 Worker，通过 HTTP 上传、保存、规则确认和后台求解，再下载 Excel 与 ZIP。它不读取真实学校 Excel，不使用外部模型服务，不修改生产部署。

| 场景 | 班级 | 每班可排格 | 课程安排 | 真实 CP-SAT | 独立硬违规 |
| --- | ---: | ---: | ---: | --- | ---: |
| 小学 | 2 | 20 | 38 | OPTIMAL | 0 |
| 初中 | 3 | 25 | 72 | OPTIMAL | 0 |
| 高中行政班 | 2 | 30 | 58 | OPTIMAL | 0 |

另有 7 项固定班会。初中包含班级课时差异；高中使用周六和自定义夜间时段，没有周末配额。小学软偏好最优代价为 420，独立验课表按实际安排重新计算，和模型结果相等。

小学追加故意冲突的教师禁排规则，真实 Worker 返回 INFEASIBLE，不能发布、没有新课表预览，并且没有复用上一轮成功课表。未知规则、无匹配对象、重复时间格、非法数字、超容量、固定课程与教师禁排冲突、共享教师固定和非固定课冲突等由回归用例覆盖。独立验课表还会主动篡改输出，证明能够发现错误。

`report.json.coverage_matrix` 由实际通过的场景生成，覆盖导入确认、周期课时、班级差异、固定活动、学科禁排、教师冲突、教师禁排、每日上限、软代价、规则确认、任意时段命名、空表阻断、Excel/ZIP 和无解后旧结果隔离。它证明这些具体能力，不证明全部学校规则、全校规模性能或真实 AI 服务已验证。

## 接下来推进方向

1. **统一业务问题合同。** 时间格、教学任务、参与者、课时需求、资源和规则分别建模。用明确 ID 建立关系，旧表格只是适配器。可用时段不等于必须上课；班级、教师可以有各自的可用范围。课时可按整个周期、指定集合或配置的分组约束，早晚与周中周末只是用户可选的分组。
2. **补足时间表达。** 当前落地入口仍以星期一至星期日为周期日；下一步支持任意周期长度、A/B 周、指定日期和例外，增加开始/结束时间与重叠判断。名称不同的时间格不能被默认视为互不重叠。
3. **规则按原语组合。** 先支持次数上下限、固定/禁排、连堂/不连堂、间隔分散、同步/错开、资源容量和条件联动；每项统一作用范围、时间集合、硬软属性及例外。编辑、AI 草案、验证、编译和解释共享能力注册信息，未实现的语义不能标为可执行。
4. **从结果到教务行动。** 输出逐项偏好代价、可核查的无解冲突证据；再推进锁定课位和最小改动调课。场地、跨校区、选科走班和值班通过资源和任务扩展纳入，并各自增加真实验收。

当前不应再增加单校姓名开关或按“白天/晚自习”分叉的独立业务模型。每轮以一个明确的用户业务需求、一个可执行规则或资源原语及正负场景验收推进。
